## 1. Motivation
  - Goal: improve the standard learned query indicator with metric-aligned
    evidence and reach ScanRefer mIoU >= 0.515.
  - Current story: B0 proved strong candidate masks can coexist with poor
    ranking; B1 recovered to 0.502; B2 tests a calibrated supervision target.
  - Missing mechanism: B1/B2 confidence heads consume query latent state but
    never inspect the query's predicted mask or its selected scene content.
  - Role: B3 tests the causal hypothesis that direct mask-conditioned scene
    evidence is necessary for reliable query ranking.

## 3. Analysis & Direction
  ### 3.1 Effective Directions
  - Replacing the analytic occupancy score with a learned indicator improved
    mIoU by 0.169, confirming that query ranking is learnable.

  ### 3.2 Failed Directions
  - B0's language-conditioned occupancy field could not rank strong mask
    candidates: oracle mIoU 0.847 versus top-1 0.202.

  ### 3.3 Untested Mechanism
  - No completed model lets confidence directly inspect foreground and
    background scene features induced by its own soft mask.

  ### 3.4 Conclusion
  - Add a differentiable mask-evidence path while retaining B1's hard
    indicator supervision. This isolates information availability from B2's
    supervision-calibration hypothesis.

## 4. Experiment Plan
| # | ID | Config Path | Purpose / Hypothesis | Expected Result | Priority | Depends On |
|---|----|-------------|----------------------|-----------------|----------|------------|
| 1 | AdaRES-B3 | configs_song/model_paper5/adares_b3_mask_evidence_res.yaml | Direct mask-conditioned scene evidence improves query ranking | > B1 mIoU 0.502 and target 0.515 | P0 | AdaRES-B2 |

  For query q and superpoint m, let p_qm = sigmoid(z_qm) and scene feature v_m.

  f_q_pos = sum_m p_qm v_m / (sum_m p_qm + epsilon)

  f_q_neg = sum_m (1-p_qm) v_m / (sum_m (1-p_qm) + epsilon)

  indicator_q = MLP(LN([q, f_q_pos, f_q_pos - f_q_neg]))

  Padding is removed from both normalized sums. Gradients flow through query,
  mask logits, and scene features.

## 7. Risk Assessment
  - Code risk: normalized soft-mask pooling can become unstable for empty/full
    masks; denominator clamping and real-scene gradient testing cover this.
  - Resource risk: the evidence tensor adds modest decoder memory; real-scene
    smoke passed while B2 was occupying both GPUs.
  - Data risk: no new data or validation-derived parameter is introduced.
  - Fallback: if B3 does not beat B1, close mask-evidence pooling and inspect
    explicit query competition rather than tune weights or thresholds.
