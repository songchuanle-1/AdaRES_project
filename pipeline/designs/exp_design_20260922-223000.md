# AdaRES C1/C2 Ranking-Repair Design

## Goal And Baseline

- Goal: ScanRefer mIoU >= 0.5150.
- Champion and direct baseline: `AdaRES-B4-E30`, mIoU 0.5094.
- Warm-start checkpoint:
  `/bak_home/songcl/Project/AdaRES_project/AdaRES_checkpoints/adares_b4_query_competition_res/20260921_210214/best.pth`.
- Both candidates preserve the B4 architecture and parameters. Only the
  indicator-ranking objective changes.

## Common Notation

For expression sample `b`, let `z_i = (z_i^+, z_i^-)` be the two-class
indicator logits of query `i`, and define the ranking score

```text
s_i = z_i^+ - z_i^-.
```

Let `M_i` be the query mask and `Y_t` a ground-truth object mask. Define the
oracle query quality as

```text
u_i = max_t IoU(sigmoid(M_i) >= 0.5, Y_t > 0.5).
```

## C1: Listwise Expected-Mask Ranking

### Ranking Distribution

```text
p_i = softmax(s_i / tau_s)
q_i = softmax(u_i / tau_u)
```

The listwise objective is the KL divergence from the model ranking
distribution to the oracle-IoU distribution:

```text
L_rank = KL(q || p)
       = sum_i q_i (log q_i - log p_i).
```

Its score gradient is

```text
dL_rank/ds_i = (p_i - q_i) / tau_s.
```

Thus a query is pushed upward in proportion to how much more oracle IoU it has
than the model currently assigns to it.

### Expected-Mask Coupling

The same probability distribution defines an expected mask:

```text
M_bar = sum_i p_i sigmoid(M_i).
```

The expected mask is supervised by

```text
L_expected = BCE(M_bar, Y) + Dice(M_bar, Y).
```

The total objective is

```text
L = L_B4 + lambda_rank L_rank + lambda_mask L_expected.
```

Fixed constants: `tau_s = 0.1`, `tau_u = 0.05`, `lambda_rank = 1.0`,
`lambda_mask = 0.5`.

### Hypothesis

B4 uses local pairwise overlap context. C1 instead supervises the global
ordering of all queries and ties that ordering to the mask objective. This
tests whether top-1 selection fails because the ranking problem was too local.

## C2: Hard-Negative IoU Margin

Choose the best query and the hardest confidently wrong query:

```text
a = argmax_i u_i
b = argmax_{j: u_j <= u_a - delta} s_j.
```

Optimize the IoU-scaled hinge objective

```text
L_hn = max(0, m_0 + lambda_iou (u_a - u_b) - (s_a - s_b)).
```

The oracle IoUs are stop-gradient targets. The active gradient is

```text
dL_hn/ds_a = -1,
dL_hn/ds_b = +1
```

when the margin is violated. Fixed constants: `m_0 = 0.1`, `lambda_iou = 1.0`,
`delta = 0.05`.

### Hypothesis

B4 improves average competition context, but top-1 errors are decided by a
small number of hard negatives. C2 directly increases the margin between the
best-IoU query and the highest-scoring query that is materially worse.

## Protocol

- Warm start both variants from the same B4-E30 `best.pth`.
- Train 10 epochs, seed 1999, batch size 2, and one GPU per experiment.
- Learning rate 2e-5; optimizer and scheduler otherwise match B4.
- No validation-based tuning of temperatures, margins, loss weights, or epoch
  count.
- `min_epochs = 10` and `patience = 10` prevent premature stopping.

## Evaluation And Controls

- Metrics: mIoU, Acc@0.25, Acc@0.50, spmIoU, spAcc@0.25, spAcc@0.50.
- Efficiency: active queries, latency, and peak memory when measured.
- Direct control: B4-E30 under the identical initialization and inference
  protocol.
- A candidate is useful if it exceeds mIoU 0.5094. The phase target remains
  mIoU >= 0.5150.
- C1 and C2 are structurally distinct: global listwise distribution matching
  plus expected-mask coupling versus sparse hard-negative margin correction.

## Risks

- C1 may collapse the ranking distribution or blur the expected mask if the
  score entropy becomes too low.
- C2 may update only a small number of hard-negative samples per batch.
- Warm-start adaptation cannot prove gains from scratch, but it is the
  appropriate protocol for testing a correction on the current champion.
- ScanRefer validation is used only for the fixed scheduled checkpoints, not
  for tuning the new constants.
